# Git

A git workbench for the repo of the focused terminal: four columns side by side, **Branches** (Local / Remote / Stashes), **History** (the working tree on top, then a drawn commit graph for this branch, every branch or one branch's log), **Files** (what the selected row changed, with `+n −n` counts) and **Diff** (that file's change, in a rounded box). As many columns show as fit; the expanded tab shows all four. Everything works from the keyboard with vim-ish moves and lazygit's letters, and everything works with the mouse: click, shift-click and cmd-click rows, tick a file's checkbox to stage it, double-click, right-click for a row's actions, drag a commit onto another to squash or move it and drag a branch onto another to merge or rebase. The diff stages, unstages or discards whole hunks or picked lines, takes review notes for an agent, asks AI about a change, and during a merge or rebase says which side each change comes from. `b` is a fuzzy branch switcher and `u` undoes the last commit, amend, rewrite, merge, pull or reset made here. Writes run in background herdr-core terminals whose output stays in a copyable log; a merge or rebase conflict, a failed hook or your review notes go to a coding agent with one key. When a merge or rebase stops on conflicts, `v` opens a Conflicts pane beside the tab: the conflicted files, a lazygit-style chunk picker (ours / theirs / both, undo), Ask AI, and continue / abort with a failure box you can hand to an agent.

## How it behaves

- Follows the focused pane's folder (else the space's folder), on that pane's machine. A mod pane in focus (the Conflicts pane, a diff pane) has no folder: the panel keeps the repo it had in that space. Not in a repo: "Not a git repository: <folder>".
- Refreshes: a local folder watch on the work tree and git dir marks it dirty (checked every 800ms; a change in the git dir reloads branches and history too); a full reload at least every 30s; PRs from `gh` every 2 minutes. `ctrl-r` forces both. Cursors stay on the same commit and branch when the lists change under them.
- What the right-hand columns show follows the left: History's cursor picks the subject (Working changes, or a commit); Files lists the subject's files; Diff shows the Files cursor's file (a folder: everything under it, tracked files then up to 30 untracked). `enter` on a stash shows its files and diff instead (esc or × goes back).
- **Moving**: `1 2 3 4` columns, `h`/`l` (`←`/`→`, `tab`/`shift-tab` wrap) the column left / right, `j`/`k` move, `gg` / `<` / `home` top (a lone `g` waits 400ms, since it is reset or pop on some rows), `G` / `>` / `end` bottom, `ctrl-u`/`ctrl-d` (`,` `.`, page keys) half a page, `[`/`]` the column's tabs (Local / Remote / Stashes, This branch / All; from a branch's log back to This branch), `enter` opens (files, the diff, a branch's log), `/` live filter for the column, `x` the row's actions as a menu, `escape` backs out (the range, the filter, a branch's log, a stash, a command's output, the failure banner), `q` hides the panel (not in the expanded tab), `?` the all-keys card. A footer chip, the `x` menu and the `?` card are built from the same action table, so every row's keys are listed there.
- **Anywhere** (a column's own key wins): `c` commit, `P` push, `p` pull, `f` fetch all (`--prune`), `b` branch switcher, `u` undo, `i` Ask AI, `S` stash all (optional message, untracked included), `@` command log (last 20; a running one opens in `terminal.peek`), `m` continue / skip / abort the operation in progress (also open the Conflicts pane, Ask AI, open conflicted files in the editor, mark them resolved), `v` the Conflicts pane while there are conflicts (in History and Diff `v` stays range / line select), `ctrl-r` refresh. Custom commands from `config.json` win over everything.
- **Branches**: `space` check out (remote: switch to its local or create a tracking one; a branch checked out in another worktree: "Go to its worktree", which selects the space with a terminal in that folder or opens a new space there), `enter` its log in History, `n` new branch from here, `M` merge menu (merge / `--no-ff` / `--ff-only` / `--squash`), `r` rebase menu (`--autostash`, `--update-refs`, `--rebase-merges`, `--autosquash`, interactive in a new tab), `f` fast-forward from upstream, `R` rename, `d` delete (local: force only after confirming when not merged and no merged PR; or local + remote; remote rows: delete the remote branch), `D` clean up merged / closed / gone branches (keeps HEAD, the base, main, master, develop, worktrees, open PRs), `o` open its PR, `y` copy the name. On a remote's header: `enter`/`space` fold, `f` fetch that remote. Stashes: `enter` its files, `space` apply, `g` pop, `d` drop, `n` branch from it. The `merged` tag needs the branch to be in `git branch --merged <base>`, not sitting exactly on the base commit and not checked out in another worktree.
- **History**: on Working changes, `c` commit, `a` stage / unstage all, `enter` its files. On a commit: `s` squash and `f` fixup into the commit below, `r` reword (a prompt with the subject; the body is kept), `R` reword in your editor (new tab), `d` drop, `A` amend staged changes into it, `e` edit (stop there in a rebase), `a` reset author / set author / add co-author, `F` fixup! commit, `S` autosquash, `ctrl-j`/`ctrl-k` move down / up, `space` detached checkout, `g` reset soft / mixed / hard, `t` revert, `T` tag, `C` mark for cherry-pick, `V` cherry-pick the marked onto HEAD, `n` new branch, `o` open in the browser (GitHub, GitLab, Bitbucket), `y` copy menu (hash, subject, message, URL, author), `enter` its files. `v` or `shift-↑/↓` selects a range, cmd-click picks commits one by one: then `s` / `f` (a contiguous set) squash or fixup them into the commit below, `d` drops them, `ctrl-j`/`ctrl-k` (contiguous) move the block, `C` marks, `y` copies the hashes, `v` / `esc` clears. Rewriting a pushed commit asks first; rewrites only work in This branch and never on merge commits. Rewrites run `git rebase -i --autostash --rebase-merges` with `seq-edit.pl` as the sequence editor, so no editor appears.
- **Files** (working tree): `space` stage / unstage the file (a conflicted file: mark resolved), `enter` review its diff, `a` stage all / unstage all, `d` discard (unstaged only, or everything; an untracked file is deleted after asking), `o` open in the editor (`config.json` `editor`, default nvim) in a split, `A` ask AI, `p` send the review notes, `y` copy the path, `t` tree or flat (remembered), `-` / `=` fold / unfold every folder. On a folder: `space` stage / unstage everything under it, `enter` fold / unfold, `d` discard it all (asks; untracked files deleted), `A`. A commit's or stash's file: `enter` the diff, `o` editor, `y` copy path. A filter (`/`) lists matches flat.
- **Diff** (`4`, `enter` from Files, or a click on a line): `j`/`k` and `↓`/`↑` jump to the next / previous hunk (or conflict), landing on its first change (`}`/`{` too); `v` starts selecting lines, and then `j`/`k` move a line at a time; `ctrl-d`/`ctrl-u` 15 lines; `space` stages the hunk or the picked lines (on the staged side: unstages them), `d` discards them from the working tree (asks), `a` writes a note on the line or lines, `X` deletes the notes on this line, `p` sends the notes to an agent, `A` asks AI about the selected lines (else the whole change: your question, or "explain and flag anything risky", with the diff, the branch, and during an operation which side is which; a commit's change works too), `J`/`K` next / previous file, `e` (or `o` outside a conflict) opens the editor at that line, `escape` clears the selection, then goes back to Files. On a conflict: `o` / `t` / `b` keep current / incoming / both (the file is rewritten without that conflict's markers; stage it with `space` in Files once none are left). A commit's full `git show` or a command's output scrolls with `j`/`k`, `ctrl-d`/`ctrl-u`, `G`; `esc` goes back.
  - Staging lines works as lazygit's: a patch of the chosen lines (`git apply --cached --recount`; `--reverse` to unstage; `git apply --reverse` to discard). An untracked file stages whole.
  - Review notes are kept per repo (shared `git.notes`) until sent; sending lists each note with its file, lines, side and the lines it is about, and asks the agent to address them. Sent notes are removed.
  - Sides: during a merge "current · <branch>" (ours) and "incoming · <other>" (theirs); during a rebase "upstream · <onto>" and "your commit · <branch>"; cherry-pick "picked", revert "reverting". The incoming side's files are `git diff --name-only` from the merge base (or the picked commit's parent) to `MERGE_HEAD` / `REBASE_HEAD` / `CHERRY_PICK_HEAD` / `REVERT_HEAD`.
- **Mouse**:
  - Click a row: it gets the cursor and its column the keyboard. In History, shift-click makes a range from the cursor and cmd-click (ctrl-click) picks commits one by one. In Files, a press in the checkbox lane (the first 30px) stages or unstages the file or folder; a second click on a selected folder folds it; a click on a remote's header folds it.
  - Double-click: a branch switches to it (a stash shows its files), a commit rewords it, Working changes commits, a file opens its diff, a diff line writes a note.
  - Right-click any row or diff line: the row's actions as a menu at the pointer (right-clicking inside a picked range keeps the range).
  - Drag commits (This branch only; dragging from a picked range drags the whole range) onto another commit: a menu offers Squash into it, Fixup into it, Move just above it. Drag a branch onto another: onto the current branch, merge it (or `--no-ff`); the current branch onto another, rebase onto it (or `--update-refs`); another onto a local branch, switch there and merge; and Rebase <src> onto <dst> (switches to it).
  - In the diff: click a line for the cursor, shift-click extends, drag selects; the hunk under the pointer shows its buttons. The branch pill opens the switcher, `↓n` pulls, `↑n` pushes, `⌄` opens the sync menu.
- **`b` branch switcher**: type to filter; letters in order match ("pfl" finds perf-lab). Local branches (most recent first), then remote branches nobody tracks, at most 12, and "Create branch …" when the text names no local branch. `↑`/`↓` (`ctrl-p`/`ctrl-n`, `ctrl-k`/`ctrl-j`) choose, `enter` switches (a worktree's branch goes to its space; a remote one gets a tracking branch; create runs `git switch -c`), `esc` closes.
- **`u` undo**: commits, amends, rewrites, merges, pulls, resets, reverts and cherry-picks made from this panel remember where HEAD was (last 30). `u` asks, then puts the branch back: a commit or amend comes back as staged changes (`reset --soft`), a rewrite that left the files as they were also `--soft`, anything else `reset --keep` (uncommitted changes stay; refuses if they'd be lost). It refuses on another branch than the one changed, and says when commits made since go too.
- **Commit**: `c` with something staged opens the commit dialog at once; otherwise (and from the `⌄` beside Commit) a menu: commit staged, stage all and commit, amend with staged, stage all and amend (amending a pushed HEAD asks), commit in your editor (new tab). The dialog is lazygit's: a one-line **Commit summary** with its length (amber past 50, red past 72) over a multi-line **Commit description**; `tab` / `shift-tab` switch boxes (the active one has the `accent` border), `enter` in the summary commits, `enter` in the description adds a line, `ctrl-s` (also `cmd-s`, `alt-enter`, `cmd-enter`, `ctrl-enter`) commits from either, `esc` cancels; the footer shows the keys for the box in use, with Cancel and Commit. It runs `git commit -m <summary> [-m <description>]`. The repo's draft opens with it: esc or a failed commit keeps what was typed (per repo root in shared `git.commitDrafts`), only a commit that moves HEAD clears it.
- **Pull / push / prune**: `p` runs `git pull`; the sync menu adds pull `--rebase --autostash`, push, force push (with lease, after asking), fetch all `--prune`, clean up merged / closed / gone branches, and the custom commands. `P` pushes `-u origin HEAD` with no upstream, offers `--force-with-lease` when diverged, refuses when only behind ("pull first"). The shipped custom command `ctrl-p` prunes: `git fetch --prune`, then deletes local branches whose upstream is gone.
- One write at a time; a second shows "Wait for the running git command to finish". Click the running title to peek at it. A failure (not a conflict stop) shows the failure banner and its output in the Diff column.
- **AI hand-offs** (`i`, the banners' buttons): with conflicts it writes a resolution prompt (the operation, the files, what ours / theirs mean during a rebase, "don't continue, commit or push"); after a failure it sends the command and its last 300 output lines, saying it's most likely a commit hook for `git commit` and `--continue` ("fix and `git add`, don't commit, I'll retry"); otherwise the review notes. A menu offers up to 8 agents in the active space (sent with `hc send`), a new tab of the first installed agent, or Copy prompt. The AI banner then follows that agent; when it is done, Continue finishes the merge / rebase and Retry re-runs the failed command.
- Conflicts pane: opens only when asked (`v`, Resolve, the `m` menu, the diff's Open resolver), focused and holding the keyboard; if one is already in the tab it is focused instead. It refreshes every 1.5s and closes itself once no operation is in progress (two looks in a row). It starts on the first file with chunks. Two places, as in lazygit: the file list (`↑↓`/`j k` files, `enter`/`→`/`tab` into the chunks, `r` keep, `d` delete for one-sided files) and the chunks (`←→`/`h l` conflict, `↑↓`/`j k` ours/theirs, `space`/`enter` keep the chosen side, `esc`/`tab` back to the files). Anywhere: `o`/`t`/`b` keep ours/theirs/both, `z` undo, `[ ]` file, `a` Ask AI for this file, `i` for all, `e` editor (new tab, `$VISUAL`/`$EDITOR`/nvim), `c` continue, `A` abort (confirm), `f` Ask AI about the failure, `x` dismiss it, `esc` in the list leaves (`pane.go right`). Clicks select files, conflicts and sides.
  - A pick rewrites the file (`writeTextFile` against the text it read, so an edit elsewhere is caught and reloaded) and keeps an undo stack per file. Picking the last conflict runs `git add` (as lazygit does), marks the file resolved and moves to the next undecided file (wrapping round). `z` on a decided file runs `git checkout -m` to make it conflicted again and writes the earlier picks back. Keep runs `git add`, Delete `git rm`.
  - "Ours" and "theirs" are labelled: during a rebase ours is the upstream being rebased onto and theirs your commit.
  - Ask AI (a / i) writes the conflict prompt for that file or all of them; Ask AI on a failure (f) sends the command, exit code and last 300 lines, noting that a failed `--continue` with everything staged is most likely a commit hook. Both offer the same menu: agents in the space, a new agent tab, Copy prompt.
  - Continue / Skip / Abort run like the panel's writes (a login-shell core terminal, `GIT_EDITOR=true`).
- Pop-out: opens the repo in a tab of its own ("Git · repo", one per space, reused) and hides the side panel; the same button in that tab closes it and brings the panel back. Coming back to that tab later gives it the keyboard again (Herdr only hands a mod pane `focus` on `pane.go`, so the panel takes it when its pane becomes the focused one; only then, so a popup over it keeps the keys).
- Leaving: `go:left` (and `cmd-alt-←`) gives the keyboard back to the tab (`focusTab()` in `panel.js`: its focused pane, and the agent chat's reply box while the Chat view shows). The panel no longer widens its column; a width an older version widened to is put back once.

## Watch out

- `place: "none"`: `pond-tabs` adds it to the right-hand panel (see Install); or open it as a pane: `herdr-app do pane.split '{"direction":"right","mod":"git"}'`. `mod.open` does not apply (no overlay in `mod.json`).
- In a narrow side panel only one or two columns show: the column switcher and `1`–`4` / `h` `l` reach the rest. Pop out (or widen the panel past 1080px) for all four.
- Pop-out hides the panel's column and collapse shows it again wherever the layout has the `git` block (`panel.js`); as a pane, pop-out still opens the tab and collapse just closes it.
- The folder name `git` is hardcoded: icons `mods/git/*.svg`, `${appHome()}/mods/git/config.json`, `${appHome()}/mods/git/seq-edit.pl`, and `tab.new {mod: "git"}`. Rename the folder and these break.
- No dependency on `gitview` (github.com/ChmaraX/herdr-gitview): Files and the diff are plain `git`. The footer copies gitview's look. The `leader` mod in this repo reads `git.hasKeys` and runs `git.expand`/`git.collapse`, but Git works without it.
- Needs `git`, `perl` (commit rewrites and drags), `sh`; `gh` is optional (PR tags, cleanup by PR state). `o` and PR links use macOS `open`. The editor runs `nvim` per the shipped config.
- Remote spaces: reads and writes run there, but there is no folder watch (refresh every 30s or ctrl-r) and `seq-edit.pl` is a local path, so commit rewrites fail on remote repos.
- The commit graph must be laid out from parents (no `git log --graph` ASCII) and reuse freed lanes so lines stay vertical.
- Virtual-list rows can't hold handlers: clicks come from the list's `on_item_click` / `on_item_secondary_click`, and modifiers, click count, the checkbox lane and drags from a `on_mouse_down` on the list's wrapper (it fires before the row's click). The drag target row is computed from the pointer's y, the list's scroll `offset()` and the row height (divide event positions by `settings().zoom`). A click right after a drag is ignored for 60ms.
- `on_size_change` sits on the body `div`, not the mod's root (a root size handler rendered the mod blank on 0.1.17).
- A key in a column's own actions wins over the global one with the same letter (`f` is fixup on a commit, fast-forward on a branch, fetch elsewhere; `S` autosquash on a commit, stash elsewhere); custom commands win over both.
- `g` waits 400ms before running its action (reset, pop) so `gg` can still go to the top.
- GPUI has no blur event for a focus handle: poll `is_focused()` and redraw only on change.
- Conflicts pane: chunk picks write files on this computer only (`writeTextFile`); for a remote space it points to the editor or AI. A mod's `mod.json` must exist before its folder is first seen, or Herdr docks a copy into the shown layout. Its list rows use the list's `on_item_click`, never per-row handlers (they drew nothing), and one row height (per-row sizes drew nothing). Never use a key event's `cx` after an `await` (wrap the work in `cx.spawn`), or a refresh flag sticks and the pane freezes.
- Diffs are capped at 4000 lines; reads are bounded by exec's 30s limit, writes are not.
- Diffs up to 2000 rows are plain rows (each takes presses, shift and drags, hover shows hunk buttons, and wraps long lines); longer ones are a virtual list (one-line rows, plain clicks, keys, no hunk buttons). A `ScrollHandle` keeps the cursor in view in the plain list.
- Line staging needs the hunk's own file header: a folder's diff resets it at every `diff --git`. Conflicted files show the working file (markers parsed there), not `git diff`'s combined diff. A pick writes the file with `sh -c 'printf "%s" "$1" > "$2"'` (the text as an argument, so very large files can hit the argument limit).
- Undo only knows what this panel did, in this session (the stack is per copy and not saved).
- A closed copy must clear `git.tabHasKeys` (`close()`), or the leader takes the next `e` for a collapse.

## Done when

- `herdr-app check ~/.config/herdr-app/mods/git` passes.
- Split it beside a terminal in a repo and widen it past 1080px: four columns, no top bar; History's header shows the branch pill and `↓n ↑n ⌄`. Narrow it under 780px: three columns and the top bar with the column switcher; under 500px one.
- Branches lists local branches with `↑n` (`ansi3`) / `↓n` (`ansi4`) / `gone` tags; `]` shows Remote, `]` again Stashes.
- History starts with Working changes; `j` onto a commit fills Files with its files and `+n −n` counts and Diff with the first file's change.
- Files lists the working tree flat with checkboxes; clicking a checkbox stages the file; `t` shows a tree.
- `enter` on a file with two hunks, `space` stages only the hunk under the cursor (`git diff --cached` shows it); `j` jumps to the next hunk, `v`, `space` stages one line of it. Hovering a hunk shows Stage / Discard / Ask AI.
- `c` with something staged opens the commit dialog; type a summary, esc; `c` again shows it. `enter` commits; the spinner shows while the hook runs and `@` lists the command with ✓. `u` then asks and brings the changes back staged.
- `s` on an unpushed commit squashes it into the one below with no editor appearing. Dragging a commit onto another offers Squash / Fixup / Move; Move reorders them.
- Dragging another branch onto the current one offers Merge; `u` undoes the merge.
- `b`, a few letters of a branch name, `enter` switches to it; a name that matches nothing offers Create branch.
- Right-click a commit: its actions at the pointer; shift-click another: the footer shows `squash n`.
- A rebase with a conflict shows the red banner with the step bar; `i` offers the space's agents and Copy prompt; `m` → `a` aborts it.
- A commit blocked by a failing pre-commit hook shows "pre-commit hook failed" with the output's last lines; Retry runs it again, Fix with AI offers the agents.
- `cd` the terminal into another repo: the panel follows within a second.
- `space` on a branch checked out in another worktree switches to (or opens) that worktree's space; a new branch on the base with only uncommitted work shows no `merged` tag.
- During a conflicted merge, Files shows `both sides` on the conflicted file and `▼ <branch>` on a file merged in cleanly; the conflicted file's diff shows ▲ current and ▼ incoming parts, and `t` keeps the incoming one.
- `a` on a diff line, a note, then `p` offers the space's agents; after sending, the note is gone.
- Expand (pop-out, or `e` with the leader), switch to another tab and back: `2` moves to History.
- `herdr-app check ~/.config/herdr-app/mods/git-conflicts` passes and `node mods/git-conflicts/test_logic.mjs` prints `ok`.
- Merge a branch that conflicts: the banner offers Resolve (v); `v` opens the Conflicts pane with the keyboard in it, on the first file with chunks; `enter`, `↓`, `space` keeps theirs for the first conflict, the file's count drops, and after the last one the file turns green as `resolved` and is staged. `z` brings it back.
- A file deleted on the other side shows its own changes against the base; `r` keeps it (green, `kept`), `d` deletes it.
- With every file decided, `c` continues; a continue blocked by a failing hook shows the red failure box with the hook's error, and `f` offers to send it to an agent.
